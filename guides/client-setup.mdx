Scramjet's client-side integration is intentionally minimal: include a single generated script, call `initBootstrap()`, and you get back a fully initialised `Controller` object that manages the service worker, transport connection, and every proxied `Frame` your page creates. The bootstrap script itself is served dynamically by the server at `bootstrapInitPath` (default `/bootstrap-init.js`) and embeds the correct configuration inline, so your front-end code needs no knowledge of individual asset paths.

## How the Client Bootstrap Works

When your page calls `initBootstrap()`, the following happens under the hood:

1. The service worker at `swPath` is registered via `navigator.serviceWorker.register()`.
2. An `init-bootstrap` message is posted to the SW with the full `BootstrapOptions` config.
3. The SW downloads and caches all required assets (scramjet bundle, WASM, controller scripts, transport client) from jsDelivr CDN into IndexedDB.
4. Once assets are cached, the SW loads the scramjet controller SW script by evaluating it directly, then broadcasts `init-bootstrap-done` back to the page.
5. The `loadRest()` function on the page loads the scramjet bundle, controller API, and utils scripts, instantiates the chosen transport client, and returns a new `Controller`.

## Step-by-Step Setup

<Steps>
  <Step title="Include the Bootstrap Init Script">
    Add the dynamically-generated init script to your page. It exposes `initBootstrap()` on `window` and can be loaded via a classic `<script>` tag or a dynamic import:

    ```html
    <!-- Option A: classic script tag -->
    <script src="/bootstrap-init.js"></script>

    <!-- Option B: dynamic import inside a module -->
    <script type="module">
      await import('/bootstrap-init.js');
    </script>
    ```

    The file is generated by the server from `bootstrapInitPath` (default `/bootstrap-init.js`). It inlines the serialised `BootstrapOptions` config so no additional arguments are required.
  </Step>

  <Step title="Call initBootstrap()">
    `initBootstrap()` registers the service worker, triggers asset downloads inside the SW, and — once everything is ready — loads the controller scripts on the page and constructs a `Controller` instance:

    ```js
    const controller = await initBootstrap();
    ```

    The returned `controller` is an instance of `Controller` from `@mercuryworkshop/scramjet-controller`. It holds references to the service worker, the active transport, and all `Frame` objects your page creates.
  </Step>

  <Step title="Wait for the Controller to Be Ready">
    After construction, the `Controller` needs to complete its internal handshake with the service worker and load the scramjet WASM binary. Call `controller.wait()` before creating any frames:

    ```js
    await controller.wait();
    ```
  </Step>

  <Step title="Create a Proxied Frame">
    Call `controller.createFrame()` with an existing `<iframe>` element, or with no arguments to have the controller create one for you. The returned `Frame` object wraps the element and handles all URL rewriting:

    ```js
    // Attach to an existing iframe
    const iframe = document.getElementById('proxy-frame');
    const frame = controller.createFrame(iframe);

    // Or let Scramjet create a new iframe (you must append it yourself)
    const frame = controller.createFrame();
    document.body.appendChild(frame.element);
    ```
  </Step>

  <Step title="Navigate to a URL">
    Call `frame.go(url)` with an absolute URL to load a site through the proxy. Scramjet encodes the URL using the active codec and sets it as the iframe's `src`:

    ```js
    frame.go('https://example.com');
    ```
  </Step>
</Steps>

## Complete Example

```html
<!DOCTYPE html>
<html>
<head>
  <title>Scramjet Proxy</title>
</head>
<body>
  <iframe id="proxy-frame" style="width:100%;height:600px;border:none;"></iframe>

  <script type="module">
    // Step 1: load the bootstrap init script
    await import('/bootstrap-init.js');

    // Step 2: register the SW and get a Controller
    const controller = await initBootstrap();

    // Step 3: wait for the controller <-> SW handshake and WASM load
    await controller.wait();

    // Step 4: create a Frame bound to our iframe
    const iframe = document.getElementById('proxy-frame');
    const frame = controller.createFrame(iframe);

    // Step 5: navigate
    frame.go('https://example.com');
  </script>
</body>
</html>
```

## Frame Navigation Methods

Once you have a `Frame`, use these methods to control navigation:

<CardGroup cols={2}>
  <Card title="frame.go(url)" icon="arrow-right">
    Encodes `url` through the active codec and sets the iframe `src`. Triggers a full navigation to the proxied page.

    ```js
    frame.go('https://example.com/path?q=1');
    ```
  </Card>
  <Card title="frame.back()" icon="arrow-left">
    Calls `history.back()` on the iframe's content window, navigating to the previous entry in the proxied page's history stack.

    ```js
    frame.back();
    ```
  </Card>
  <Card title="frame.forward()" icon="arrow-right">
    Calls `history.forward()` on the iframe's content window.

    ```js
    frame.forward();
    ```
  </Card>
  <Card title="frame.reload()" icon="rotate-right">
    Reloads the currently proxied page by calling `location.reload()` on the iframe's content window.

    ```js
    frame.reload();
    ```
  </Card>
</CardGroup>

## Controller Configuration

The `Controller` exposes two distinct config objects:

| Property | Type | Purpose |
|---|---|---|
| `controller.config` | `Config` | Proxy-level settings: URL prefix, asset paths, WASM path, and the codec `encode`/`decode` pair. Override at construction via `new Controller({ config: { ... } })`. |
| `controller.scramjetConfig` | `ScramjetConfig` | Rewriter-level settings passed deep into the scramjet engine: feature flags (`syncxhr`, `captureErrors`, `sourcemaps`, etc.), global function name identifiers, masked file paths, and per-site flag overrides. Override at construction via `new Controller({ scramjetConfig: { ... } })`. |

When using `initBootstrap()`, both configs are set from the `BootstrapOptions` passed by the server. You can still construct the `Controller` manually if you need full control:

```js
import { Controller, config as defaultControllerConfig } from '@mercuryworkshop/scramjet-controller';

const controller = new Controller({
  serviceworker: sw,
  transport: myTransport,
  config: {
    prefix: '/~/sj/',
    codec: {
      encode: (url) => btoa(url),
      decode: (url) => atob(url),
    },
  },
  scramjetConfig: {
    flags: {
      sourcemaps: true,
      captureErrors: true,
    },
  },
});
```

## Switching Transports at Runtime

You can hot-swap the active transport without recreating any frames. This is useful for letting users choose between transports or for reconnecting after a network change:

```js
import LibcurlClient from '@mercuryworkshop/libcurl-transport';

const newTransport = new LibcurlClient({
  wisp: `wss://${location.host}/wisp/`,
});

controller.setTransport(newTransport);
```

<Note>
  You **must** await `controller.wait()` before calling `controller.createFrame()`. The method throws immediately if the controller's internal `ready` promise has not yet resolved, because the service worker handshake and WASM load must complete first.
</Note>

<Warning>
  Some Scramjet features — including `SharedArrayBuffer`-backed sync XHR — require the page to be served with Cross-Origin Isolation headers (`Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp`). If these headers are absent, those features are automatically disabled but the rest of the proxy continues to work. Check `self.crossOriginIsolated` in your page to detect the environment.
</Warning>

<Tip>
  Call `controller.setTransport(transport)` at any time to swap transports at runtime without reloading the page or losing the active frames. All pending and future requests through existing `Frame` instances will immediately start using the new transport.
</Tip>
